# 语音任务墨水屏

基于 Seeed Studio XIAO ESP32-C3、INMP441 麦克风和中景园
ZJY420S08W0G01 4.2 英寸黑白墨水屏。设备按住按键录音，将音频流上传到电脑，
Python 网关可使用百度语音或本地 faster-whisper 识别中文，并可调用 DeepSeek 按
时间、地点、事情整理后返回设备显示。

当前远程仓库中的版本是已完成的阶段 0 基线。后续开发将在新分支进行，并逐步把依赖
电脑的识别链替换为设备直连云端的产品流程。

## 当前功能

- 墨水屏按顺时针旋转后的 `300×400` 竖屏坐标显示。
- 屏幕按外壳分为 A1-A4 四个任务栏和一个固定功能栏，每个任务栏最多显示 3 行
  16 点阵文字，每行最多 16 个全角字符或 32 个半角字符。
- A1、A2 分别由两个实体按键控制，同时操作两个按键控制 A3；A4 当前仅显示默认
  提示，等待后续硬件扩展。
- 短按切换已有任务的未完成/已完成状态，分别显示空心/实心方块。普通任务完成时
  写入最近 30 条记录，取消完成时按历史 ID 精确撤销对应记录。
- 按住至少 500ms 开始语音输入，松开后提交识别，最长 60 秒。
- 保留按下后的 500ms 预录音频，避免丢失开头语音。
- 静音按住 3 秒会立即重置对应区域，不需要等待松开。
- 无语音和操作失败使用无方块的中文提示，技术错误仅写入串口。
- 支持 GB2312 一级汉字、按需补充汉字以及可打印 ASCII 字符的 16 点阵显示；当前
  补充字表包含二级汉字“馨”。
- 使用 SSD1683 `0x24/0x26` 双 RAM 黑白差分刷新，连续 4 次差分刷新后执行
  1 次全刷。
- 服务端默认在识别完成后自动删除临时 WAV；诊断模式可选择只保留无语音、非待办或
  识别异常的失败样本。
- 首次使用或已保存 Wi-Fi 连接失败时，设备建立 `EinkTask-Setup` 配网热点；凭据验证
  后保存在 NVS。正常联网时可通过设备局域网 IP 访问管理后台。
- 管理后台可维护 Wi-Fi、识别网关及预留的云 API 配置，并显示 4 个活动任务和最近
  30 条已完成记录；任务状态通过 LittleFS 跨重启保存。
- 百度 STT 与 DeepSeek 密钥通过本地 `tools/cloud_config.env` 配置，不写入仓库。
- DeepSeek 判定输入不是待办时，仍按普通三行任务结构显示
  `事情:[未识别到待办事项,请重试]` 并允许切换方块状态，但该占位任务带有持久化的
  `history_eligible=false` 标记，无论是否短按完成都不会进入最近 30 条记录。
- 功能区使用称呼、固定场景名称和颜文字的三行布局。自动调度开启后，新任务、完成
  操作、临近/到期时间点和每日温馨互动时段会触发确定性场景更新，不再由 AI 判断场景。
- Python 网关把精确时间和常见时间段转换为隐藏时间坐标；设备通过 SNTP 校时，持久化
  每条任务的时间范围及临近/到期去重状态。

当前使用厂商 `0xFF` 黑白差分刷新波形和完整 `400×300` RAM 窗口。任务更新
只修改软件 framebuffer 中对应的任务栏，但每次仍传输完整新旧帧，因此这是视觉上的
局部更新，不是硬件子窗口局刷。该方案已通过实机测试，可避免非零 X 子窗口引起的
跨区更新、半屏反黑、旧内容迁移和文字叠加。

## AI 功能区（重点开发）

最下方第五栏是独立的 AI 功能区。它不保存任务、不显示完成方块，也不进入任务历史；
目标是根据四个任务栏的结构化状态，用简洁、实用且有温度的内容帮助用户判断当前
最值得注意的事情。当前第一轮只显示固定场景名称，用于验证时间解析、优先级和刷新
时机；动态 AI 文案尚未接入。

### 固定布局与称呼

功能区使用稳定的三行布局：第一行左侧为固定称呼，第二行为一句提醒，第三行右侧为
程序选定的颜文字。例如：

```text
大卫,
还有30分钟提交报告哦!
                             >_<
```

- 首次开机的手机配置页面提示用户填写称呼，可提供“朋友”作为可跳过的默认值；之后
  可在手机后台修改。
- 称呼保存到独立、版本化的 NVS 设备资料中，不写入任务缓存，也不需要发送给 AI。
- 称呼最多 6 个中文字符或 12 个显示列，并且只能使用当前字库支持的字符。
- AI 提醒变化时称呼保持不变；称呼改变时才重绘完整功能区。
- 第二行提醒不得换行，最多 32 个显示列。超长结果应重新组织成短句，不能直接截断。
- 所有屏幕文案使用半角标点，不使用 emoji 或字库未包含的符号。

### 内容优先级

同一时刻只显示一种内容，按以下优先级选择：

1. 到期确认：任务的精确时间已到或模糊时间窗口结束，每条任务只触发一次。
2. 临近任务：距离精确时间或时间窗口开始不足 30 分钟，每条任务只触发一次。
3. 下一步建议：新任务写入且没有更高优先级提醒。旧设计中的冲突、聚合和拆解统一
   收敛到这一类型，程序不替用户判断任务关系。
4. 每日总结：正常任务被标记完成且没有更高优先级提醒时触发，不再依赖固定晚间时间。
5. 温馨互动：08:00-20:00 每 3 小时检查一次，仅在不会覆盖有效高优先级内容时显示。
6. 默认欢迎：开机或没有其他有效提示时显示“欢迎使用电纸便利贴!”。

### 情绪代码与表达边界

AI 只返回隐式情绪代码，不能直接返回姓名、颜文字或自由格式排版。设备通过固定白名单
映射第三行颜文字：

| 情绪代码 | 颜文字 | 典型场景 |
| --- | --- | --- |
| `smile` | `^_^` | 默认欢迎、一般建议 |
| `concern` | `>_<` | 临近任务、到期确认 |
| `thinking` | `._.` | 后续保留的思考类文案 |
| `happy` | `^o^` | 后续保留的出行类文案 |
| `cheer` | `^-^` | 完成较多、每日总结 |

当前颜文字完全由固定场景映射：临近和到期确认使用 `concern`，总结使用 `cheer`，
其他场景使用 `smile`。未来接入动态文案后，AI 也只能返回白名单代码；未知代码回退
为 `smile`。这里的情绪只是界面表达方式，不能用于推断用户真实情绪。

### 刷新与调度

AI 功能区采用事件触发和时间触发结合的方式：

- Python 网关返回 `exact/window/none` 时间类型以及 `start_at/end_at` Unix 时间戳；设备
  将其与任务修订号、提醒状态一起写入版本化 LittleFS 缓存。
- ESP32 使用北京时间 SNTP，每 15 秒检查一次；时钟未同步时任务仍可录入和显示，但
  不执行定时提醒。
- `凌晨/早上/上午/中午/下午/傍晚/晚上/深夜`映射到固定时间窗口；`稍后`、`下班后`、
  `有空时`等不可靠表达保持 `none`，不会编造具体钟点。
- 离线或重启后根据持久化时间坐标恢复调度。越过多个节点时只触发当前最高优先级状态，
  已发送标记防止同一任务重复提醒。
- 温馨互动仅在 08:00、11:00、14:00、17:00、20:00 后的 5 分钟窗口内触发，错过后
  不补播；到期确认、下一步建议和总结有 3 小时显示保护期。

### 服务端职责与返回协议

规则引擎负责时间坐标、临近/到期判断、完成事件、优先级和重复限制。DeepSeek 当前只
负责判断是否为待办并整理 `time/place/event`，不再返回功能区场景。以后接入动态文案时，
模型只能根据程序指定的场景组织短句，不能改变场景或编造时间、地点和任务顺序。

未来动态文案的建议响应为：

```json
{
  "type": "due_soon",
  "text": "还有30分钟提交报告哦!",
  "mood": "concern",
  "source_task_ids": ["task-123"],
  "valid_until": "2026-08-07T15:00:00+08:00",
  "next_check_at": "2026-08-07T15:05:00+08:00",
  "fingerprint": "..."
}
```

设备只校验、缓存和显示最终结果，复杂判断保留在服务器。任务数据需要逐步补充稳定的
任务 ID、原始时间表达、标准时间、`due_at`、时间精度、地点、事情和完成状态；只有
`exact` 以及经过明确产品规则配置的时间窗口可以用于定时提醒。

### 开发顺序与验收

1. 已完成称呼配置、NVS 存储、三行渲染器和六种固定场景。
2. 已完成时间坐标协议、模糊时间窗口、SNTP、本地调度、提醒去重和任务缓存迁移。
3. 实机验证新任务、临近、到期、完成总结、重启恢复和定时温馨互动。
4. 建立AI输出长度、支持字符和情绪代码校验。
5. 在稳定调度器之上接入由场景约束的动态短文案，并保留固定模板兜底。

第一轮以固定场景名称验证调度准确性，不调用 AI 生成提醒文案。验收重点是时间坐标、
事件优先级、每任务只提醒一次，以及断网、重启和跨天后的状态恢复。

## 硬件接线

所有模块使用 `3.3V` 并共地，不要连接 `5V`。

### 墨水屏

| ZJY420S08W0G01 | XIAO 引脚 | GPIO | 说明 |
| --- | --- | ---: | --- |
| VCC | 3V3 | - | 3.3V 电源 |
| GND | GND | - | 公共地 |
| DIN / SDA | D10 | 10 | SPI MOSI |
| CLK / SCL | D8 | 8 | SPI SCK |
| CS | D1 | 3 | SPI 片选 |
| DC | D2 | 4 | 命令/数据选择 |
| RST / RES | D3 | 5 | 复位 |
| BUSY | D4 | 6 | 高电平表示忙 |

墨水屏的 MISO 不需要连接。面板按顺时针旋转 90° 使用，A1-A4 从上到下排列，最下方
为固定功能栏。

### INMP441

| INMP441 | XIAO 引脚 | GPIO | 说明 |
| --- | --- | ---: | --- |
| VDD | 3V3 | - | 3.3V 电源 |
| GND | GND | - | 公共地 |
| SCK / BCLK | D5 | 7 | I2S 位时钟 |
| WS / LRCL | D6 | 21 | I2S 左右声道时钟 |
| SD | D7 | 20 | I2S 数据输入 |
| L/R | GND | - | 选择左声道 |

### 按键

| 按键 | XIAO 引脚 | GPIO | 控制区域 | 接法 |
| --- | --- | ---: | --- | --- |
| A1 | D0 | 2 | A1 任务栏 | 按键连接 D0 与 GND |
| A2 | D9 | 9 | A2 任务栏 | 按键连接 D9 与 GND |

按键使用 ESP32-C3 内部上拉，按下时为低电平，不需要外接上拉电阻。同时操作 A1、A2
按键选择 A3，固件使用 120ms 组合键判定窗口吸收机械按键的时间差；A4 暂无实体按键。

## 软件准备

需要安装 VS Code、PlatformIO 扩展和 Python 3。首次使用时创建 Python 虚拟环境并
安装识别服务依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

复制网络配置示例：

```powershell
Copy-Item include\network_config.example.h include\network_config.h
```

编辑 `include/network_config.h`：

- `kServerHost`：运行识别服务的电脑局域网 IPv4 地址，不能使用 `localhost`。
- `kServerPort`：默认 `18000`。

Wi-Fi 名称和密码不再写入该文件，而是通过设备配网页面录入。真实接收器配置已被
Git 忽略。

启用百度 STT 和 DeepSeek：

```powershell
Copy-Item tools\cloud_config.example.env tools\cloud_config.env
```

编辑 `tools/cloud_config.env`，填写 `BAIDU_API_KEY`、`BAIDU_SECRET_KEY` 和
`DEEPSEEK_API_KEY`。保持 `STT_PROVIDER=baidu`；只测试百度识别时可将
`ENABLE_DEEPSEEK` 改为 `false`。真实密钥文件已被 Git 忽略。

## 运行流程

1. 启动电脑端接收和识别服务：

```powershell
.\.venv\Scripts\python.exe tools\audio_receiver.py
```

2. 编译并烧录设备：

```powershell
pio run
pio run -t upload
```

3. 根据需要打开串口监视器：

```powershell
pio device monitor -b 115200
```

4. 按住 A1 或 A2 并说话，松开后等待识别和屏幕刷新；同时操作两个按键输入 A3。
   短按已有任务对应的按键可以切换完成状态。

服务端通过 HTTP chunked encoding 边接收边写入临时 WAV。录音结束后调用所选 STT，
再按配置调用 DeepSeek；完成后将显示文本和语音/待办判定响应头返回设备。识别完成、
识别失败或设备判定本段为静音时都会删除临时文件，因此 `recordings` 目录通常为空。
HTTP 收发位于 `audio_receiver.py`，STT 选择、任务结构化与文本兜底集中在
`recognition_pipeline.py`，百度和 DeepSeek 的协议适配位于 `cloud_services.py`。

当前云 API 通过 Python 网关接入，ESP32 仍连接 `kServerHost`，尚未实现设备直接连接
百度或 DeepSeek。这样可以保留现有流式上传并避免在 ESP32-C3 内存中保存完整录音。

## 字库与显示

- `assets/gb2312_level1_16.bin`：3755 个 GB2312 一级汉字和按需补充字模；当前共
  3756 字，补充字符为“馨”。
- `assets/gb2312_level1_unicode_map.bin`：Unicode 到字库位置的映射。
- `assets/asc16_printable.bin`：英文、数字和可打印标点。
- `tools/font_extra_chars.txt`：受控补字清单；通过 `extract_gb2312_level1.py` 从完整
  HZK16 追加字模，避免嵌入完整二级字库。
- 不在字库中的字符显示为 `?`。

字库二进制通过 `platformio.ini` 嵌入固件。它们是文字显示所需资源，不属于已删除的
通用图片显示功能。

补字后使用完整 HZK16 重新生成资源：

```powershell
.\.venv\Scripts\python.exe tools\extract_gb2312_level1.py C:\path\to\HZK16
```

## 开发路线

### 阶段 0：稳定基线（已完成）

- 阶段 0 完成了两按键、上下两分区的语音任务基线；当前功能分支已扩展为五栏界面。
- 墨水屏采用完整 RAM 窗口差分刷新，实现稳定的视觉分区更新。
- 当前代码已上传远程仓库；后续功能从新分支继续开发。

### 第一大阶段：核心云端流程（开发阶段 1-3）

1. 配网：首次使用时由 ESP 建立手机可访问的配网页面，通过 NVS/Preferences 保存
   Wi-Fi 凭据并在以后自动连接，同时保留可重新进入配网的恢复入口。LVGL 示例只作为
   流程和界面参考，手机端页面本身由 ESP 的 HTTP/captive portal 提供。
2. DeepSeek 与显示：先沿用当前流式接收器提供的识别文本，按时间、地点、事情
   生成有边界且可校验的结构化结果并显示到对应区域；字段缺失或处理失败时保留可读
   的识别文本作为兜底。
3. 云端 STT：最后把电脑端 faster-whisper 接收器替换为云端适配器，首个目标为选定的
   百度语音接口。继续使用现有“按住时边录边上传、松开后结束并取回结果”的方法，
   并把云服务细节与录音、按键和显示逻辑隔离。

云端传输适配放在本阶段最后：配网、DeepSeek 和任务显示可以先使用现有接收器联调，
因此不会阻塞核心路径。流式输入不需要把完整录音保存在 ESP32-C3 内存中，也不设置
由内存容量决定的短录音上限；仍可保留服务策略或防异常占用所需的安全超时。完成标志
是：新设备可用手机配网，重启后自动联网，不依赖电脑即可完成录音、云端识别和结构化
显示。本阶段不要求已完成任务历史持久化。

### 第二大阶段：后台管理与次要功能

- 增加明确的 AP/管理模式和手机 Web 后台。
- 在后台中提供 Wi-Fi 切换/退出，以及语音识别和 DeepSeek 配置管理。
- 后台框架及数据接口稳定后，再实现原计划阶段 4：通过 LittleFS 等本地存储记录、
  查询和维护已完成任务；小型配置继续使用 NVS。
- 此后再补充其他次要功能和体验优化。
- 正式发布前补充后台鉴权和密钥保护；原型期可继续使用编译期 API 配置。

### 第三大阶段：硬件与容量升级

- 优先评估带 PSRAM 的 ESP32-S3 等主控。
- 扩展分屏数量时，一并重构区域配置、按键扫描和引脚分配，并重新验证墨水屏刷新、
  内存占用、功耗及异常恢复。
- 音频传输方案放在本阶段最后决定，因为它不影响前面的核心功能。分别验证两条路径：
  使用 PSRAM 保存录音后调用普通 API，以及直接连接云端 WebSocket API 流式上传。
  对比可用录音时长、延迟、内存、断线恢复、服务商限制和开发复杂度后再做取舍。
  在此之前继续沿用当前“按住时边录边上传、松开提交”的流式输入和安全超时。

### 后续待办

- 在获得稳定的面板波形和窗口时序后，再评估真正的硬件子窗口局刷。
- 保留当前 Python 接收器作为音频与协议测试工具，不再作为产品运行依赖。
- 公布或量产前，将硬编码密钥迁移到受保护的运行时配置。

## 故障排查

- 串口没有输出：关闭并重新打开监视器，重新插拔 USB 后按一次 XIAO Reset。
- 上传时串口被占用：先用 `Ctrl+C` 关闭监视器，再执行上传。
- `BUSY timeout`：检查墨水屏的 3.3V、GND、BUSY 和 RST。
- Wi-Fi 超时：检查网络配置、2.4GHz Wi-Fi 频段和信号。
- Windows 点击“打开浏览器并连接网络”后仍无法进入页面：先关闭 VPN、系统代理和
  TUN/Fake-IP 模式，忘记并重新连接 `EinkTask-Setup`；也可直接打开
  `http://192.168.4.1`。代理软件可能抢占 `msftconnecttest.com` 的 DNS/HTTP 请求，
  这种情况下请求不会到达 ESP32。
- 无法连接服务端：确认电脑与设备位于同一局域网、防火墙允许配置端口，并检查电脑
  当前 IPv4 地址。
- 百度配置错误：检查 `STT_PROVIDER`、API Key、Secret Key 和百度应用的语音识别权限。
- DeepSeek 失败：服务端会记录具体原因并回退到原始转写，不会把技术错误显示在屏幕。
- 修改 Python 服务端后仍出现旧错误：用 `Ctrl+C` 停止旧进程并重新启动服务。
- 服务端端口无权限或被占用：使用 `--port` 更换端口，并同步修改设备配置。
- 旧文字叠加或刷新异常：确认 `0x24` 保存新帧，刷新后将完整新帧同步到 `0x26`，
  并使用完整 `400×300` RAM 窗口。
- 静音长按没有自动重置：检查串口中的录音秒数，并根据现场底噪调整 VAD 阈值。
